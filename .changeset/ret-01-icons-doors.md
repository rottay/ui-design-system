"@rottay/design-system": major

Consolidate icon rendering and corpus metadata at `./icons`. Remove the unused
`./icons/full`, `./icons/corpus` and `./icons/bithire` doors without adding a
compatibility entry. Keep aggregate `./marks` and the class-specific
`./marks/brand` and `./marks/cloud` resource boundaries: they reuse canonical
implementations while preserving isolated CommonJS execution and synchronous SSR. `./icons/presets/bithire` keeps its existing bounded
inventory. The six corpus roles it consumes are preserved, as are the canonical
semantic renderer, role inventory, metadata and mark implementations.
The public map changes from 43 to 40 subpaths.
The removed metadata-only door's renderer-free module boundary is not retained;
import metadata by name from `./icons` for ESM tree-shaking. Runtime asset controls
previously exposed on `./icons/full` are retained on the canonical `./icons` door.

RET-01/D07 also removes the 328 vendor-named glyph exports from the canonical
`./icons` public API in this target major. The inventory below is derived from
the existing private catalog, not from a zero-consumer claim. Existing
app-platform consumers and 52 Showroom files import this door; their named-glyph
imports must be adapted. Apps remain outside this DS packet, and Showroom
migration is required before closing RET-01 or certifying Showroom against this
major. No claim is made that those consumers compile unchanged today.

All 282 semantic roles, corpus metadata, provenance, runtime asset governance,
`createIcon`, `BaseIcon`, size helpers and their current structural types remain
public. The private catalog and supplier/license owners used by real DS
components remain unchanged. No legacy door, private-source bridge or new
vendor-name aliases are introduced.
The complete private barrel inventory has 329 bindings: 328 vendor-named
glyphs retired below and the first-party `AlertIcon` wrapper preserved by an
explicit export from its existing leaf owner. `AlertIcon` is not a supplier
alias; it keeps the existing `BaseIcon`/`SvgIconProps` contract. The resulting
facade has 56 explicit symbols: 24 runtime values and 32 types.

Migration: choose the stable role matching product intent, not the supplier's
glyph spelling. A create-item `PlusIcon` becomes
`<Icon name="action.add" decorative />` inside an already named control, or
`<Icon name="action.add" label="Create item" />` when it supplies meaning.
Import `Icon` from `@rottay/design-system/icons`; provide `label`, or
`decorative={true}` without a label. One intent is required. Focused semantic role/preset entries
remain available for route-sized payloads.

This is not an arbitrary `SVGProps` replacement: preserve supported `size`,
`color`, `className`, `style`, `id`, `aria-describedby`, `data-testid` and
`data-part` through `IconProps`. Move `title`/`aria-label` to `label` and
explicit hidden intent to `decorative`; place events on the owning control.
Use semantic size tokens or numeric pixels, not arbitrary CSS strings for `size`.
Supplier weight/stroke options, arbitrary SVG attributes and SVG children are
not silently forwarded. App-owned custom SVGs may use the retained
`BaseIcon`/`SvgIconProps` or `createIcon`/`DSIconProps` contracts; they must not
import a supplier directly or restore removed supplier-name aliases.
