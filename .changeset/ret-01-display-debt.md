WO-RET-01 (display primitives debt lot). The deprecated `TONE_TO_CALLOUT_VARIANT` retires from the package root. It was declared as `= TONE_TO_VARIANT`: the same object reference as the kernel map under Callout's name and a narrower static type, never a second table. The consumer census (line grep plus a multi-line JSX scan over the package source, the showroom source and the `src` roots of app-bithire, app-evnto and app-platform) measured zero consumers of the name outside the Callout family: its only readers are the Classic and Rustic Callout engines and the tone-axis contract test, and all three import it from the family's contracts module, not from a barrel. The constant therefore stays in `display/callout/contracts` as a family-internal binding with its `@deprecated` tag removed, because it is no longer public and nothing is left to migrate away from; only the two public re-exports (`display/callout` and the display barrel, which reaches the package root) are gone. Callout renders exactly as before on every engine, and the contract test still proves by reference that the binding is the kernel map. The marker promised the name "for one release": no minor shipped between that promise (2026-07-18) and 3.0, and no consumer exists to claim it. Downstream apps: an import of `TONE_TO_CALLOUT_VARIANT` from `@rottay/design-system` fails at compile time on upgrade; replace it with `TONE_TO_VARIANT` from the package root, which was and remains published there, and note that it is typed as the six-key `Tone` map rather than the four-key Callout record.

```contract-diff
export .#TONE_TO_CALLOUT_VARIANT — removed; identity alias of the kernel `TONE_TO_VARIANT`, zero consumers across package, showroom and the three apps outside the Callout family; the Classic and Rustic Callout engines keep reading the same binding from the family contracts module, zero behavior change; migrate to `TONE_TO_VARIANT` from the package root (RET-01 display debt)
```
