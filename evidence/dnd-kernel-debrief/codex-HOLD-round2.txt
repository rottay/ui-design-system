**B1 — The four adapters still do not establish a working, behavior-preserving contract.**

Call-site target binding and consumer-owned stamps are now explicit. Those corrections are sound. The remaining problems are concrete:

- **Tree’s mandatory adapter fails type checking twice.** [§2.2.4(c)](/Users/daniel/Developer/Rottay/r4-recon-opus/evidence/dnd-kernel-debrief/index.md:581) supplies `{key: TreeEngineKey}` where `DragPayload.key` must be `string`. The actual [TreeEngineKey](/Users/daniel/Developer/Rottay/r4-recon-opus/packages/core/src/components/primitives/display/tree/runtime/tree-behavior/index.ts:19) is `string | number`. Separately, `getTargetProps({key: nodeKey})` omits the required `position` in its declared `TTarget`. I reproduced **TS2344** and **TS2345** using the document’s interfaces and TypeScript 5.9.3, entirely in memory. These are contract failures under the document’s own statement that the adapters are mandatory, not illustrations. Preserve numeric identity; distinguish bound target identity from resolved destination, or provide a valid alternative.

- **Tree’s source eligibility changes.** Today [Tree computes](/Users/daniel/Developer/Rottay/r4-recon-opus/packages/core/src/components/primitives/display/tree/engines/modern/index.tsx:263) `isDraggable = propDraggable && !disabled` per row and attaches `onDragStart` accordingly. The adapter only disables the whole session with `!propDraggable`; its source factory then returns `draggable: !disabled` for every row. Stamping `data-draggable={isDraggable || undefined}` does not disable native dragging. The contract needs per-source eligibility that preserves disabled rows.

- **The ColumnMenu foreign-drag reconciliation is false.** [Lines 504–514](/Users/daniel/Developer/Rottay/r4-recon-opus/evidence/dnd-kernel-debrief/index.md:504) assume every foreign `text/plain` value produces `indexOf === -1`. A foreign drag can contain an existing column key. I executed the revision-base normalizer, reorder helper and drop callback with no local session, columns `[a,b,c]`, external text `"a"`, and destination `"c"`: the result was **`[b,c,a]`**. The [current handler](/Users/daniel/Developer/Rottay/r4-recon-opus/packages/core/src/components/structures/workspace/column-menu/index.tsx:417) accepts that drop; the proposed session-only handler rejects it. Rejection may be desirable, but it must be an expressly declared behavior change with a pin covering a **matching** foreign key.

- **Stamp ownership alone does not preserve stamp behavior.** SavedViews’ current [dragover handler](/Users/daniel/Developer/Rottay/r4-recon-opus/packages/core/src/components/patterns/data/saved-views/engines/modern/index.tsx:196) leaves the previous target intact when the source is hovered again. The new self-target resolver returns `null`, which explicitly clears it. Thus dragging `a → b → a` changes the displayed target. This contradicts invariant 1’s unchanged-stamps promise unless declared separately.

- **Exactly-once termination and N10 disagree.** [§2.2.3](/Users/daniel/Developer/Rottay/r4-recon-opus/evidence/dnd-kernel-debrief/index.md:479) requires synchronous ref consumption; §2.2.4(d) says the session clears after the callback; [N10](/Users/daniel/Developer/Rottay/r4-recon-opus/evidence/dnd-kernel-debrief/index.md:1325) demands failure if the ref clears before `onDrop`. Saving the session locally, clearing the ref, then passing the saved payload/target preserves both arguments and prevents reentrant commitment. I verified that counterexample. N10’s designated assertion would remain green. Specify terminal reservation before external callbacks, rendered-state cleanup, callback exception handling and announcement order independently.

**B2 — Keyboard declarations are connected, but the API still cannot drive its delegated consumers.**

The HTML5 scope correction, explicit candidate-versus-commit distinction, Home/End exclusion and axis refusal rules are improvements. Home/End returning `null` preserves Kanban’s existing arrow-only move mapping.

However:

- **There is no delegated session entrypoint.** [The result API](/Users/daniel/Developer/Rottay/r4-recon-opus/evidence/dnd-kernel-debrief/index.md:395) exposes `move(intent)`, `commit()` and `cancel()`, but none accepts a payload or opens a keyboard session. Delegated mode installs no key handler. Starting from `session === null`, a ColumnMenu button cannot identify which column to move. Tree’s proposed destination picker also cannot supply an arbitrary node and before/inside/after destination through four relative intents. Calling a synthetic HTML5 handler would contradict the declared abstraction. This requires a concrete typed entrypoint and one complete delegated adapter.

- **The documented delegated configuration does not type-check.** Tree is instructed to use `keyboard: {mode: 'delegated'}`, but [SortableKeyboardOptions](/Users/daniel/Developer/Rottay/r4-recon-opus/evidence/dnd-kernel-debrief/index.md:730) requires `orientation` and `resolveKeyboardTarget` for every mode. The in-memory check produced **TS2739**. Use mode-specific option types consistent with the promised behavior.

- **Repeated candidate movement lacks a defined input.** `resolveKeyboardTarget(payload, intent)` receives no current candidate. During grab mode the committed data remains unchanged, so successive arrows need an explicitly defined way to advance from the previous candidate. Requiring an unstated closure over returned session state leaves this contract incomplete.

- **The direction source is missing.** The pure resolver requires `rtl`, but neither session options nor keyboard options provides it. Invariant 6 prohibits importing the existing i18n direction authority. [resolveNavigationIntent](/Users/daniel/Developer/Rottay/r4-recon-opus/packages/core/src/components/primitives/runtime/collection/roving-focus/index.ts:68) consumes a supplied boolean; importing that function does not supply the boolean. Allow the established direction hook or expose an explicit direction input.

- **Generic announcement metadata exceeds the supplied information.** Every candidate move includes pointer dragover, while `moved` requires `crossedContainer`. The kernel neither understands `TTarget` nor receives a container projection or resolver-supplied crossing result. Define who supplies that fact and which events fire for immediate commits, which explicitly have no candidate phase.

Shipping grab mode without an adopter is not itself the blocker. The shared candidate machinery first needs a usable, specified lifecycle.

Every [StatefulRow](/Users/daniel/Developer/Rottay/r4-recon-opus/packages/core/src/components/structures/workspace/column-menu/index.tsx:1117) owns another local instance. Being declared in the same file does not expose that instance to the parent.
- Button’s pointer props notify consumer callbacks after its internal handler; they do not export its internal cancellation function. A Button dragend repair can clear Button’s instance, but cannot clear its ancestor row’s separate instance.

Specify a per-source cancellation binding or registration mechanism, or an explicit component-local cleanup boundary. Show the row/card plumbing.

The lot split also remains contradictory: lot 2’s adapter already calls the supposed combined cancellation route, although its PRE-pin must preserve both pre-repair pressed values through transport adoption. Lot 6 is described as a Button-only repair, leaving the row repair unassigned. Assign both repairs and reconcile them with the unchanged PRE-pin.

Still blocking:

- **The named browser harness cannot exercise the proposed hook as it stands.** [family-causality](/Users/daniel/Developer/Rottay/r4-recon-opus/packages/core/tests/support/family-causality/index.ts:158) injects server markup through `host.innerHTML`, reads computed styles and removes the host. [§6.3](/Users/daniel/Developer/Rottay/r4-recon-opus/evidence/dnd-kernel-debrief/index.md:1296) must name the live mount/browser-input extension or an existing suitable harness, with an owned write set. Merely running in Chromium does not test native DnD negotiation.

- **Leaving and removal coverage is weaker than claimed.** C3 requires dragleave behavior, but source props say it appears “when the family declares it”; no such option exists. C5 only removes a target and subsequently supplies `dragend`. It does not cover source removal while the session owner remains mounted, or commitment against a removed/invalidated target. Non-null session fields are not live validity checks.

- **Tree’s declared dropEffect addition conflicts with unchanged tests.** Its existing [dragover test helper](/Users/daniel/Developer/Rottay/r4-recon-opus/packages/core/src/components/primitives/display/tree/tests/Tree.modern-engine-advanced.test.tsx:206) supplies `clientY` but no `dataTransfer`. An unconditional `event.dataTransfer.dropEffect = 'move'` fails that fixture. Specify a PRE-lot fixture correction or another deliberate treatment; “existing tests unchanged” cannot silently absorb it.

- **Kanban’s announcement repair has no consistent lot.** §0.7 assigns repeated-outcome repair to an operability lot. The lot table provides operability lots only for SavedViews/ColumnMenu and Tree, while §6.2 requires the improved outcome in Kanban’s transport lot 5. The measured current implementation fails that requirement. Assign a declared repair lot instead of demanding it inside unchanged transport adoption.

- **The F-69 arm needs an executable admission rule.** `OWED_ARMS` currently [prints unmet obligations](/Users/daniel/Developer/Rottay/r4-recon-opus/packages/core/scripts/check/family-cut/index.mjs:1431); adding an entry there does not enforce adoption. The proposed positive test only requires an import, which may be unused. Require actual invocation/wiring, define transitive adapter treatment, and name the measurement, blocking check and drill files. Preserve the new requirement, but do not mistake its declaration for a sufficient instrument design.

N10’s invalid mutation requirement and the false C6/N11 ColumnMenu baseline are additional B5 failures described under B1.
