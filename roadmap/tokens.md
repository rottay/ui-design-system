# Design System Tokens Lane

This lane carries the **color/token engine** work the owner approved from the proposals inbox
on 2026-07-07 (P-03, P-04, P-06 — the token-and-generation slice of round 1). Where the
`engine-modern` lane fixes the WIRING of the modern engine (tokens, dark elevation, states,
effects, drains, galleries), this lane re-engineers the token PIPELINE and VALUES themselves:
every first-party artifact becomes a mechanical build product (TOK-01), the color layer becomes
an OKLCH derivation from tenant seeds so ANY tenant palette yields an even, contrast-verified
ramp without per-tenant design work (TOK-02), and the dead DaisyUI layer is retired so the
architecture docs stop lying about what modern is (TOK-03). Each WO builds on machinery that
ALREADY exists on disk (the bithire artifact generator, `compileBrandTheme`, the tint scale, the
contrast validator) — the pattern of this repo is consolidate-and-elevate, not green-field.

The three approved proposals map 1:1 to the three WOs: TOK-01 from P-06, TOK-02 from P-04,
TOK-03 from P-03. Proposal P-07 (tenant-independent light/dark axis) stays **WITHDRAWN**
(owner 2026-07-07): there is no user-facing light/dark toggle; each tenant defines ONE palette
and correctness on that surface is owned by WO-ENG-03 (elevation) and WO-TOK-02 (ramp
derivation per tenant palette). Nothing in this lane may reintroduce a scheme axis.

**Relationship to the `engine-modern` lane.** TOK-02 deliberately waits for WO-ENG-06 (color
purity — components must consume tokens before the token VALUES are re-engineered) and TOK-03
waits for WO-ENG-08 (the theme.css drain deletes the dead DaisyUI mappings before the
dependency is dropped). Where this lane touches files the ENG lane also edits
(`compilers/brand-theme`, `tokens/css/artifacts/**`, `scripts/engine-token-audit.mjs`), the
orchestrators **coordinate windows before claiming** — the same no-conflict discipline the
README applies to the external co-editor. The `scripts/engine-token-audit.mjs` ratchet (created
by WO-ENG-01) is the lane-wide mechanical gate family; WOs here EXTEND it with new counters,
never fork it.

**External co-editor (binding).** app-evnto WO-IDN-06 extends the SAME
`packages/core/scripts/build-vertical-artifacts.mjs` and generator spec that WO-TOK-01
generalizes. The written ordering law is in WO-TOK-01's coordination note: whichever of the two
executes second re-verifies parity before certifying.

### WO-TOK-02 OKLCH color engine with generated ramps
- **Outcome** — `compileBrandTheme` derives perceptually-even OKLCH color ramps from each tenant's seed colors, with **ramp derivation per tenant palette**: the derivation keys on the tenant's OWN surface (a dark-surface tenant like rottay gets a dark-tuned ramp; a light-surface tenant gets a light-tuned one — there is NO light/dark toggle, owner decision 2026-07-07). State shades mix in a perceptual space, artifacts emit P3 wide-gamut values with sRGB fallbacks, every generated text/surface pairing is APCA-checked at compile time, and all first-party artifacts regenerate through the WO-TOK-01 pipeline. Any tenant seed color yields a full, even, contrast-verified palette mechanically — no per-tenant design work.
- **Why** — P-04 (proposals.md round 1, APPROVED 2026-07-07): the biggest whitelabel win. Verified state of the color layer: the compiler passes tenant seed hex straight through (`packages/core/src/compilers/brand-theme/index.ts:183-195` sets `--ds-color-primary`/`-secondary`/`-accent`/status vars verbatim from the palette), and dark values are separate HAND-PICKED fields with no derivation (`darkPrimaryColor`/`darkSecondaryColor`/`darkAccentColor`/`darkBackgroundColor` at index.ts:110-113 and :192-195 — `tokens/ts/brand-themes/rottay.ts` hand-picks `#FFFFFF`/`#A0A0A5` over the `#0C0C0E` canvas). The foundation ramp `--ds-color-primary-50..900` is hand-tuned hex (`packages/core/src/tokens/css/foundation/themes/default.css:20-25+`, `50:#fafafa ... 500:#171717`). The interaction tint scale `--ds-tint-{4,8,12,16,24}` mixes in NON-perceptual sRGB (`setTintScaleVariables`, index.ts:345-364: `color-mix(in srgb, var(<role>) N%, var(--ds-color-bg-primary))`). The only contrast machinery is WCAG-ratio (`contrastRatio` at `packages/core/src/_internal/a11y/contrast/index.ts:219`, AA 4.5/3 pairs at :331-338) — no APCA anywhere, and OKLCH appears only in a compiler-test fixture (`compilers/brand-theme/tests/brand-compiler.test.ts:321`).
