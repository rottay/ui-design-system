# Design System Gates Lane

This lane is the **proof wall**: it converts the DS quality claims — "premium stays premium",
"the package stays clean", "EVERYTHING is whitelabel-able per tenant", "premium is accessible" —
from confidence-by-construction into mechanical, CI-enforced proof. The owner approved the four
source proposals on 2026-07-07 (P-11 visual regression, P-14 package gates, P-05 hostile-tenant
proof, P-10 accessibility CI). **Build this lane first among the new lanes**: every later
program leans on it — the fleet migration to the headless core (`roadmap/architecture.md`,
WO-ARC-01..03) is only safe under WO-GAT-01's pixel net, the OKLCH color re-engineering
(`roadmap/tokens.md`, WO-TOK-02) is only trustworthy under WO-GAT-03's whitelabel probes and
WO-GAT-04's contrast checks, and the craft lane's motion/interaction work rides the WO-GAT-02
ratchet extensions.

**What exists today (verified 2026-07-07).** CI is `.github/workflows/ci.yml` (self-hosted
runners; jobs `detect` / `core` / `showroom` / `changeset` / `gate`): it typechecks, builds,
unit-tests with coverage, and builds Storybook — it renders **zero pixels, runs zero axe checks,
and probes zero computed styles**. No Playwright dependency exists anywhere in the workspace
(`packages/core/package.json`, `packages/showroom/package.json`). The ESLint governance plugin
(`packages/core/src/eslint/index.ts`) ships exactly 4 rules (`no-raw-html`,
`no-hardcoded-colors`, `no-db-in-components`, `no-direct-lucide`). The only contrast machinery
is the WCAG 2.2 ratio validator at `packages/core/src/_internal/a11y/contrast/index.ts`
(hex-only; skips CSS variables); a repo-wide grep for APCA returns nothing. Bundle budgets exist
for entry points only (`packages/core/scripts/analyze-bundle.mjs`, not wired into CI) and for
Storybook output (`packages/core/scripts/check-storybook-budget.mjs`, main-branch only).

**Relationship to the other lanes.** The `engine-modern` lane creates the two things this lane
gates: the mechanical ratchet (`scripts/engine-token-audit.mjs`, created by WO-ENG-01 — lane-wide
law: counters EXTEND it, never fork it) and the trustworthy render surfaces (the WO-ENG-02
per-component galleries + capture route). This lane adds no component code and no visual change;
it adds harnesses, probes, counters, and CI jobs. File overlap with other lanes is limited to
`scripts/engine-token-audit.mjs`, `.github/workflows/ci.yml`, and `packages/showroom/e2e/**`;
per-WO coordination notes below name each overlap, and orchestrators coordinate windows before
claiming (the same discipline the README applies to the external co-editor).

Lane-wide rules (binding on every WO):

- Repo: `/Users/daniel/Developer/Rottay/ui-design-system` (macOS, pnpm). All paths below are
  relative to the repo root unless prefixed. Package source is `packages/core/src/`; the render
  surface is `packages/showroom` (`@rottay/showroom`, Next.js on port 7001).
- **Gates are truth.** A WO is done when its acceptance gate passes AND the DS build/tests are
  green: `pnpm --filter @rottay/design-system run build` + `pnpm test`. Executors are
  **edit-only**; the orchestrator certifies and commits. No WO commits.
- **One Playwright harness.** All browser-driven gates in this lane live in ONE harness:
  `packages/showroom/e2e/` with a single `packages/showroom/playwright.config.ts` (created by
  WO-GAT-01). WO-GAT-03 and WO-GAT-04 add spec directories to it — whichever WO executes when
  the harness does not yet exist creates it to the WO-GAT-01 spec; no second config, ever.
- **Self-hosted only.** No external visual/a11y service (no Percy, Chromatic, or SaaS diffing).
  Baselines and reports are committed files + CI artifacts. CI runs on self-hosted runners
  (`runs-on: self-hosted` in `ci.yml`), so every new job must install its own browser binaries
  (`playwright install chromium`) and blocking screenshot baselines are the ones matching the
  RUNNER platform (see WO-GAT-01's approve flow).
- **Ratchet discipline.** Every mechanical counter added by this lane extends
  `scripts/engine-token-audit.mjs` + `scripts/engine-token-audit.baseline.json` (created by
  WO-ENG-01) or ships as a baseline JSON next to its spec; baselines are measured at
  implementation time and decrease-only. A gate that would be red on day one ships with its
  honest baseline, not a weakened assertion.
- **Sighted evidence** is captured under **both tenant palettes — a dark-surface tenant (rottay,
  `--ds-color-bg-primary: #0A0A0C`) AND a light-surface tenant (bithire or evnto)** — to
  `test-artifacts/gates/<wo>/`. There is **no user-facing light/dark toggle** (owner decision
  2026-07-07): the tenant palette decides the surface; palette switching uses nested
  `DesignSystemProvider` columns (the pattern the theme-builder page already uses).
- **Anti-sprawl.** New work = a new `### WO-GAT-NN` block in this file + a `registry.json`
  entry (`pnpm roadmap:check` forces the pairing). No new plan documents.
- No emojis anywhere. Repo docs in English. Never `git checkout/restore/reset` on directories.
  `app-bithire` is READ-ONLY. `docs-engineering` is a READ-ONLY reference. The showroom dev
  server is allowed.
- **Tenant-artifact rule (inherited).** `tokens/css/artifacts/**` are compileBrandTheme-generated
  snapshots of `tokens/ts/brand-themes/*.ts`. Any WO that changes a compiler-emitted `--ds-*`
  token regenerates the artifacts in the same WO and keeps the `compilers/brand-theme` suite
  green. (This lane only ADDS a proof-fixture theme in WO-GAT-03; it registers NO new artifact.)

Ordering is by protection value: WO-GAT-02 is cheap and needs only WO-ENG-01 — start it anytime.
WO-GAT-01 lands the pixel net as soon as the WO-ENG-02 galleries exist and BEFORE any fleet-wide
sweep (WO-ARC-01 depends on it). WO-GAT-03 rides the same harness right after. WO-GAT-04 needs
the WO-ENG-04 focus tokens as its assertion target.

## WORK ORDERS

### WO-GAT-01 Visual-regression CI on the showroom
- **Outcome** — Every PR that touches `packages/core` or `packages/showroom` runs a Playwright screenshot-diff suite over the WO-ENG-02 flagship galleries (button, input, select, card, badge, table, tabs, modal at minimum) under both tenant palettes at the 360/768/1280 viewport matrix, against baselines COMMITTED in the repo; any pixel change fails CI with expected/actual/diff images uploaded as a CI artifact, and an intended change is approved by regenerating + committing the baselines in the same PR (the reviewer sees the changed PNGs in the diff). Self-hosted end to end — no external service. This is the safety net the premium uplift, the OKLCH re-engineering (WO-TOK-02), and the headless-core fleet migration (WO-ARC-01..03) all require.
- **Why** — P-11 (proposals.md, APPROVED 2026-07-07): "the uplift is worthless if it can silently regress; this is the mechanism that keeps premium premium." Verified 2026-07-07: `.github/workflows/ci.yml` runs typecheck/build/unit-tests/Storybook-build only — no job renders a pixel; no Playwright dependency exists in `packages/showroom/package.json` or `packages/core/package.json`; the only screenshot evidence in the repo's history is the manual 82-screenshot audit set, unreproducible by CI. The showroom is the sanctioned render surface (`@rottay/showroom`, `next start --port 7001`), and WO-ENG-02 gives it a stable capture route with real variant+state galleries plus the tenant-palette axis — exactly the fixed target a diff suite needs.
- **Depends on** — WO-ENG-02 (the per-component galleries + stable capture route are the diff targets; without them the fingerprint cards make diffs meaningless).
- **Steps** —
  1. Add `@playwright/test` to `packages/showroom` devDependencies. ### WO-GAT-03 Hostile-tenant whitelabel proof
- **Outcome** — Whitelabel-per-tenant becomes a mechanically proven property: two torture BrandThemes are checked into the DS as proof fixtures (a garish dark-surface tenant and a garish light-surface tenant: clashing palette, extreme radius and density, heavy tracking, `ar` RTL locale with longest-string content) and a CI probe run renders the WO-ENG-02 flagship galleries under them, (a) capturing screenshots for the eye and (b) asserting per component part that computed color/font/radius values derive from the torture tokens — any value that does NOT move with the tenant is a hardcode and counts against a decrease-only baseline. One gate answers "is EVERYTHING per-tenant?" forever, including regressions.
- **Why** — P-05 (proposals.md, APPROVED 2026-07-07): "today whitelabel confidence is by construction, not by proof." Verified 2026-07-07: the first-party theme sources are exactly `packages/core/src/tokens/ts/brand-themes/{rottay,bithire,evnto}.ts` (re-exported by `index.ts` — "tenant CSS becomes a GENERATED artifact from these definitions"); nothing hostile exists to render against. The contrast validator (`packages/core/src/_internal/a11y/contrast/index.ts`) explicitly SKIPS CSS variables and non-hex values, so it cannot catch a component that ignores the tenant entirely. The i18n runtime already ships an RTL locale (`packages/core/src/i18n/locales/ar/`) — the RTL torture axis needs no new locale work. The artifact generator (`packages/core/scripts/build-vertical-artifacts.mjs`) is scoped to first-party product tenants; the torture fixtures deliberately stay OUT of `FIRST_PARTY_ARTIFACT_SPECS` and compile at render time via `compileBrandTheme`, so no fake product artifact is ever published.
- **Depends on** — WO-ENG-02 (the flagship galleries + capture route are the probe surface). NOTE (not a dependency): the probe is strongest after WO-ENG-06 drives modern hardcoded colors to 0/0 — until then the baseline carries the audit's known offenders and ratchets down. Coordination: shares the `packages/showroom/e2e/` Playwright harness with WO-GAT-01 — whichever executes second reuses the existing `playwright.config.ts`; never a second config.
- **Steps** —
  1. Create `packages/core/src/tokens/ts/brand-themes/torture.ts` exporting `tortureDarkBrandTheme` and `tortureLightBrandTheme`: deliberately garish clashing palettes (e.g. magenta primary / acid-green accent / amber semantic overrides) on a near-black surface (dark fixture) and a glare-white surface (light fixture), extreme surfaces (radius at both extremes across the scale, densest density, heavy shadows), heavy typography (wide tracking, strong weight bias), and distinct chrome values for every bounded section (controls/table/cardComponent/modal/tabs/sidebar/layout) so EVERY themable channel visibly moves. Re-export from `brand-themes/index.ts` with a doc comment marking them PROOF FIXTURES (never product tenants, never artifact-registered). Add a unit test that `compileBrandTheme` compiles both without error.
  2. Add a torture capture page to the showroom on the WO-ENG-02 capture-route pattern: the flagship galleries rendered under the two torture themes via `DesignSystemProvider` + `compileBrandTheme`, one column per fixture, plus an RTL column (`dir="rtl"` + the `ar` locale from `packages/core/src/i18n/locales/ar/` + a longest-string content fixture) to prove mirroring and no clipped overflow.
  3. Computed-style probes: add `packages/showroom/e2e/whitelabel/torture.spec.ts` to the shared harness. For a DOCUMENTED probe list per flagship component part (color, background-color, border-color, border-radius, font-family; `direction` on the RTL column), assert the computed value equals the compiled torture token value where the theme defines that channel, and — as the hardcode detector — assert it DIFFERS from the same part's value under the rottay tenant wherever the two themes differ. A part whose value does not move with the tenant is recorded as a violation.
