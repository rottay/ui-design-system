## Verdict

OLA 5 is **not accepted as a completed wave**.

Claude implemented only the application-boundary gate expansion from Phase 1.
Phases 2–5 — shared typography and density, semantic motion, the six P0
component families and the BitHire Candidates canary — were not implemented.

The Phase 1 gate is accepted after Codex corrected its coverage, terminology,
metadata and executable tests. It remains deliberately labeled

No new component is proposed for certification from this delivery.

## Findings in Claude's Phase 1 delivery

1. Native reconstruction scanning only traversed `features/` and `ui/`, so it
   omitted production code under `app/`, `vertical/` and other roots.
2. Every raw color in every feature stylesheet was called “shared chrome”.
   That conflated shared primitive repair with app-owned domain expression.
3. Supplier detection only recognized a narrow `from "package"` shape and
   missed subpaths, dynamic imports, `require()` and side-effect imports.
4. Tenant branch detection hardcoded two customer slugs rather than detecting
   concrete tenant selectors generically.
5. The new baseline entries had generic reasons but no owner, despite the
   prompt explicitly requiring owner and removal reason.
6. The new detectors had no focused executable tests. A broken detector could
   therefore pass against a baseline generated by the same broken logic.
7. The TypeScript comment stripper was regex-based and could truncate valid
   source containing URL strings.
8. Raw font and shadow detection initially produced false positives for
   `var(--ds-*)` values because of regex backtracking.
9. The handoff correctly disclosed that i18n-bypass was not implemented and
   correctly refrained from claiming visual evidence.

## Codex remediation

- Scans native interactive reconstruction across all production TSX/JSX under
  the application source tree while excluding tests, specs and stories.
- Limits raw shared-chrome literals to explicit shared roots:
  `src/styles`, `src/ui`, `src/vertical/surface` and
  `src/features/_shared`.
- Detects raw color, radius, duration, font-family and shadow independently
  without flagging tokenized `var(--ds-*)` values.
- Detects direct supplier imports through normal imports, subpaths, dynamic
  imports and `require()`.
- Detects concrete tenant selectors generically while permitting a generic
  `[data-tenant]` scope.
- Resolves legal DS application hooks only from production DS CSS and
  production compiler-emitted channels; tests and documentation cannot
  legalize an application write.
- Replaced regex comment stripping with a string-aware scanner that preserves
  URLs and removes line/block comments without changing line structure.
- Added an owner and category-specific removal reason to every baseline entry.
- Added five focused Node tests and chained them into `pretest` before the
  live gate.

## Inventory findings accepted as diagnosis only

Claude's late typography/density inventory is directionally useful but is not
implementation:

- semantic type roles currently use `pageTitle`/`sectionTitle` rather than the
  requested generic `heading`/`title`;
- the Modern engine does not yet consume the semantic role chain end to end;
- Arabic-safe font fallback remains incomplete;
- density has substantial CSS math but no single scoped JS runtime contract;
- control geometry is not yet coordinated with the density authority;
- semantic motion still lacks the requested hover, focus, reveal and error
  recipes.

These findings become continuation inputs. They do not close DS-A006,
DS-A007 or DS-A008.

## Required continuation

6. migrate one bounded Candidates canary only after DS proof is green;
